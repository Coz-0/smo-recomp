# Rules for tools/lifter/sdklift.py (SMO). No addresses and no code: only which SDK functions to lift and where to stop.
#   family <regex>   every game import whose name matches and that sdk.elf defines is a root (lifted, then installed as
#                    the import's handler)
#   rootall <regex>  every FUNCTION symbol of sdk.elf that matches is a root (reached through method tables at run
#                    time, which the static closure cannot follow); only game imports are installed as handlers
#   ctors <regex>    SDK static constructors (.init_array) that directly call a function matching: lifted, and run (in
#                    .init_array order) before the game starts, as the console's loader runs the SDK module's
#   datafuncs <regex> every code pointer stored inside sdk DATA objects whose symbol matches (method tables, function
#                    pointer data) is a root
#   root <name>      an extra root
#   cut <name>       calls to it go to the host handler of that name (game imports are cut by default)
#   wrap <name>      lifted, but calls to it go to the host handler of that name (which may call the lifted code)
#   trap <name>      calls to it stop with the name
#   lift <name>      lift the SDK's own code even though the game imports the name
